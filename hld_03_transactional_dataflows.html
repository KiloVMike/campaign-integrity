5.1 Create, Submit & Decide
Standard review cycle bound cryptographically to revision hash
1. Marketer ➔ API: Create POST /v1/campaigns with Idempotency-Key.
2. Transaction: Claim Key & Insert Inserts Campaign + Revision 1 (DRAFT) + Audit row.
3. Marketer ➔ API: Submit POST /v1/.../submit locks row, transitions Rev 1 ➔ IN_REVIEW.
4. Reviewer: Request Changes Mandatory note logged; Marketer edits (Rev 2 DRAFT created & submitted).
5. Transaction: Approval Binding Locks row, validates current Rev 2 in IN_REVIEW, computes SHA-256 hash.
6. Commit: Bound Decision Inserts Decision row bound to Rev 2 ID + Hash. Rev 2 ➔ APPROVED.
Rule BR-2: Decision records exact revision ID and content hash. Approval cannot exist without an immutable revision target.
5.2 Edit Post-Approval / Schedule
Copy-on-write mutation atomically revokes schedule & approval
1. Marketer Edits Approved Campaign PATCH /v1/campaigns/CMP-1042 (e.g. Budget ₹5L ➔ ₹8L).
2. BEGIN Transaction: Exclusive Lock SELECT * FROM campaigns FOR UPDATE.
3. Invalidate Previous State Revision 2 marked SUPERSEDED. Prior approval invalid for scheduling.
4. Copy-on-Write Fork Inserts Revision 3 DRAFT with new budget; updates current_revision_id.
5. Revoke Active Schedule Cancels schedule SCH-7001 (reason: REVISION_SUPERSEDED).
6. Atomic COMMIT Emits 2 audit events. Returns 200: approvalInvalidated=true.
Rule BR-3: Edit and schedule cancellation execute in the SAME transaction. Zero window where a schedule targets superseded content.
5.3 Single Atomic Schedule Gate
Four strict eligibility checks evaluated under PostgreSQL row lock
1. Marketer Initiates Schedule POST /v1/.../schedule with revision ID, hash & launch time.
2. BEGIN: Exclusive Lock SELECT campaign FOR UPDATE; claims Idempotency-Key.
3. Check 1: Current Revision? Verifies req.revisionId == campaign.current_rev_id.
4. Check 2 & 3: Approved & Hash Match? Verifies state=APPROVED and decision.hash == revision.hash.
5. Check 4: Uniqueness? Verifies no active SCHEDULED row exists for campaign.
6. COMMIT or ROLLBACK If all pass: inserts schedule + audit. Else: ROLLBACK + 409 Conflict.
Rule BR-1 & Invariant: active_schedule(c) ⇒ current_rev.state=APPROVED ∧ decision.rev_id=current_rev.id ∧ decision.hash=current_rev.hash.
Concurrency Guarantee: Exclusive row locks prevent double scheduling and eliminate review/edit race conditions.
