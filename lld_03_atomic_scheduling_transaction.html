Transaction Execution Pipeline
Phase 1: Claim Idempotency Key INSERT INTO idempotency_keys
Claim key in IN_FLIGHT state. If key already exists with committed response, return cached response immediately.
Phase 2: Acquire Row-Lock SELECT * FROM campaigns WHERE id = $1 FOR UPDATE
Locks campaign row exclusively. Serializes all concurrent review, edit, and schedule attempts across all API instances.
Phase 3: Four Invariant Assertions ROLLBACK ON FAILURE
1. Current Revision: req.revisionId == campaign.current_revision_id (else 409 REVISION_STALE)
2. Approved State: current_revision.state == APPROVED (else 409 APPROVAL_INVALID)
3. Cryptographic Hash: decision.content_hash == current_revision.content_hash (else 409 HASH_MISMATCH)
4. Schedule Uniqueness: No active schedule exists (else 409 ALREADY_SCHEDULED)
Phase 4: Atomic Commit INSERT schedule + audit + COMMIT
Inserts schedule row, emits CAMPAIGN_SCHEDULED audit event, stores response in idempotency table, and commits transaction.
