Atomic Gate Invariant
active_schedule(c) ⇒ current_rev(c).state = APPROVED ∧ decision.rev_id = current_rev(c).id ∧ decision.content_hash = current_rev(c).content_hash
“The campaign that gets scheduled is the exact campaign that was approved.”

1. Relational Schema & Storage

  • campaigns: Container row. Holds current_revision_id and acts as row-lock target (SELECT FOR UPDATE).
  • revisions: Append-only immutable tree. Stores objective, audience, channel, budget, state, and SHA-256 content hash.
  • decisions: Reviewer decisions bound strictly to revision ID and content hash.
  • schedules: Holds active or cancelled schedules. Partial unique index guarantees one active schedule per campaign.
  • audit_events: Tamper-evident append-only audit log. Update and delete revoked.

2. State Machine & Copy-on-Write

  • 5 Core States: DRAFT ➔ IN_REVIEW ➔ (CHANGES_REQUESTED) ➔ APPROVED ➔ SUPERSEDED.
  • Copy-on-Write Mutation: Editing an approved proposal supersedes revision, revokes prior approval, and cancels active schedule atomically.
  • Hash Invalidation: Any modification to material fields alters SHA-256 hash, causing immediate approval invalidation.
  • Deterministic 409 Conflicts: Stale revision or hash mismatch returns clear error code with current snapshot.

3. Atomic Scheduling Transaction

  • Exclusive Row-Lock: SELECT * FROM campaigns FOR UPDATE serializes all concurrent actions.
  • Check 1 (Current Rev): Verifies requested revision equals campaign current revision.
  • Check 2 (Approved State): Verifies revision state is strictly APPROVED.
  • Check 3 (Hash Binding): Verifies decision content hash matches current revision hash.
  • Check 4 (Uniqueness): Asserts no active schedule exists. Inserts schedule + audit atomically.

4. Modules & Clean Boundaries

  • Domain Core: Pure TypeScript models, state machine, eligibility logic, and canonical hashing. Imports nothing from Express or SQL.
  • Application Layer: CampaignService, ReviewService, ScheduleService, IdempotencyService.
  • Mobile App: Screens, ViewModels, pure domain helpers, local repositories, SQLite outbox sync.
  • Server Persistence: PostgreSQL repository implementations of domain ports.

5. API Contracts & Outbox Sync

  • Idempotency Header: Client passes UUID Idempotency-Key for all state mutating commands.
  • Crash Defense: Mobile writes intent to SQLite outbox before network dispatch. Recovers after process kill.
  • Duplicate Suppression: Server claims key in database. Replayed requests receive exact stored response.
  • Audit Attribution: 100% of state transitions record actor ID, revision, hash, and request ID.

6. Security & Duties Enforcement

  • Separation of Duties: Service enforces actor_id ≠ campaign.creator_id. Reviewers cannot approve their own campaigns.
  • Author Restriction: Marketer cannot approve any campaign; review role strictly isolated.
  • Timeouts Are Failures: Network disconnects never advance state. Zero optimistic boolean drift.
  • Evolvability (ADR-001): Extension point ready for dual multi-party approvals above budget thresholds.
